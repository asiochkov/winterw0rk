ВАЖНО: НЕ использовать светлую тему из `current_tokens.json` (там `bg:#F7F7F8`, `tx:#111111`) —

Акцент (ice-blue) — только для активных/фокусных/прогресс-элементов и первичных кнопок.
Никогда не заливать весь экран синим. Никакого фиолетового "AI-градиента". Никакого
неонового sci-fi свечения.

### Spacing (база 4px)
`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96` px — никаких произвольных значений между ними.

### Радиусы
```
xs: 8px   sm: 10px   md: 12px   lg: 16px   xl: 20px   hero: 24px   pill: 999px
```
Правило: чем крупнее поверхность — тем больше радиус; у мелких контролов — меньший.

### Типографика
Шрифт: нейтральный гротеск (Inter / Geist / SF Pro-like).
```
Display: 48–64px / line-height .95–1.0 / letter-spacing -.04em (заголовки экранов, "44px/800/-0.04em" в Planner)
H1: 32–40px / 1.05
H2: 24–28px / 1.1
H3: 18–20px / 1.2
Body: 15–17px / 1.45
Small: 12–14px / 1.35
Numeric (таймеры, метрики, вес, повторы): tabular-nums обязательно
```

### Моушен
```
micro:   120–160ms  (везде используется 150ms)
standard: 220–280ms (везде используется 260ms)
complex: 380–450ms  (везде используется 420ms)
easing standard: cubic-bezier(.2,.8,.2,1)
easing out:      cubic-bezier(.4,0,1,1)
easing settle:   cubic-bezier(.16,.84,.24,1)
```
Обязательно уважать `prefers-reduced-motion`.

## 6. НОВАЯ ФИЧА: РАЗВОРАЧИВАЕМЫЙ ПЛАНЕР-КАЛЕНДАРЬ (День ⇄ Неделя)

### 6.1 Что есть сейчас
В `v7.dc.html` раздел **Planner** (`isPlanner`) уже существует, но реализован как список задач
(to-do list) с вкладками **НЕДЕЛЯ / МЕСЯЦ / БЭКЛОГ** (`plTabs`, `plIsWeek`, `plIsMonth`):
- Неделя: полоска из 7 дней-кнопок (`plWeekStrip`) сверху + под ней список задач по дням
  (`plWeek` → `d.tasks`), каждая задача — карточка с чекбоксом, тегами (due/repeat/priority),
  сворачиваемыми подзадачами и контекстным меню (⋯).
- Месяц: сетка 7×N ячеек-дней (`plMonthCells`) с точками-индикаторами загрузки дня, ниже —
  список задач выбранного дня.

Это **список задач**, а НЕ временная шкала с часами. Пользователь прислал два референсных
скриншота другого приложения (по превью в чате — тёмный таймлайн-планер на телефоне и
светлый недельный грид-календарь на планшете), где:

- **Дневной вид (телефон):** вертикальная шкала времени с почасовыми метками слева (1:30,
  2 PM, 3 PM, 4 PM…), поверх которой лежат цветные карточки-события произвольной высоты
  (высота = длительность события), с иконкой активности, названием, редко — подзаголовком
  ("Buffer & rest zone"). Между событиями — тонкие подписи-инсайты вроде "energy rise" /
  "energy dip" / "end of sleep inertia" со стрелкой-иконкой и цветом (жёлтый/зелёный/оранжевый)
  — это подсказки об энергетических пиках дня. Текущее время отмечено тонкой красной
  горизонтальной линией, пересекающей всю ширину шкалы. В правом нижнем углу — плавающая
  круглая кнопка «+» для добавления события. Сверху — переключатель дней недели (буквы
  M T W T F S S с датами) и круглый индикатор процента (92) справа.
- **Недельный вид (планшет):** классическая сетка календаря — колонка на каждый день недели,
  внутри каждой колонки — цветные блоки-события, расположенные и растянутые по вертикали
  пропорционально времени/длительности (как в Apple Calendar / Google Calendar неделя).
  Переключатель видов сверху: **День / Неделя / Месяц / Год** (сегментированный控троль),
  слева — иконки (список, почта, +).

### 6.2 Что нужно реализовать
Добавить в раздел Planner **два новых режима отображения** — **День** и **Неделя** —
как временную шкалу (timeline calendar), которые можно **разворачивать/переключать** между
собой (и с существующими Месяц/Бэклог), сохранив всю текущую функциональность задач
(чекбоксы, подзадачи, приоритет, повтор, контекстное меню, drag между днями).

**Переключатель видов** — расширить существующий `plTabs` segmented control до 4 вкладок:
`ДЕНЬ / НЕДЕЛЯ / МЕСЯЦ / БЭКЛОГ` (было `НЕДЕЛЯ / МЕСЯЦ / БЭКЛОГ`). Стиль — тот же pill-control,
что уже есть (`padding:4px;border-radius:999px;background:var(--sf1)`), только адаптировать
цвета под тёмную палитру (`--canvas-2`/`--border-standard` вместо `--sf1`/`--edge`).

**Раскрытие/сворачивание (expand):** должна быть возможность мгновенно "разворачивать" день
из недельного вида в полноэкранный дневной таймлайн — по тапу на день в недельной сетке (или
по кнопке-стрелке в углу колонки дня) экран анимированно (shared-element transition,
`--m-complex` / `420ms`, `--e-settle`) переходит из "узкая колонка дня в неделе" в "полная
дневная временная шкала". И обратно — свайпом вниз/кнопкой "к неделе" сворачивается обратно.
Это ключевое требование пользователя: **день и неделя не два отдельных изолированных экрана,
а один календарь, который разворачивается/сворачивается**.

#### 6.2.1 Дневной вид (Day timeline) — новый компонент `DayTimeline`
Структура сверху вниз:
1. **Шапка дня** — как в существующем `plWeekStrip`: 7 круглых/капсульных кнопок дней недели
   с буквой дня + числом даты + точками нагрузки под датой; активный день подсвечен акцентом
   (`--ice-500`), остальные — приглушены. Клик по другому дню в этой полоске переключает
   таймлайн без выхода из дневного вида.
2. Опционально справа от шапки — круглый индикатор дневного прогресса (кольцо, % выполненных
   задач/привычек за день), стиль `ProgressRing` из каталога компонентов.
3. **Вертикальная временная шкала:**
   - Часовая сетка с лейблами времени слева (компактный текст, `--text-3`, `12px`,
     `tabular-nums`), шаг — 1 час, высота часа — фиксированная константа (например 64–72px на
     десктопе, адаптивно на мобильном), пользователь может скроллить шкалу вертикально;
     автоскролл к текущему времени при открытии.
   - Тонкая вертикальная направляющая линия (аналог "рельсы" из референса) вдоль левого края
     блоков событий.
   - **Событие-карточка (`TimelineEventCard`):** позиционируется абсолютно по вертикали
     (`top = началоМинут * pxПerMin`, `height = длительностьМинут * pxPerMin`, минимальная
     высота ~40px чтобы короткие события были кликабельны); скруглённые углы (`radius: md/12px`
     как у остальных карточек), полупрозрачная заливка цветом категории/тега (использовать
     существующую цветовую систему тегов из Habits/Training — `cat`-цвета: TRAINING/MIND/
     BODY/FOCUS и т.п. с уменьшенной непрозрачностью фона ~15–20% и полноцветной левой
     кромкой/иконкой), внутри — название события (`Body: 15px/600`), опционально маленькая
     подпись под названием (`Small/12px/--text-3`, напр. "Buffer & rest zone"), иконка типа
     активности слева/справа (переиспользовать иконки из существующей icon-системы SVG,
     `stroke:currentColor`, 14–16px).
   - **Инсайт-метки между событиями** (`EnergyInsightLabel`): тонкая горизонтальная надпись с
     маленькой стрелочкой-иконкой (↗ рост / ↘ спад) и цветным текстом (жёлтый `--warning` для
     спада, зелёный `--success` для подъёма энергии), например «energy rise», «energy dip»,
     «end of sleep inertia» — данные приходят из уже существующей логики
     энергетических/циркадных инсайтов приложения, если её ещё нет — завести как отдельный
     сервис `energyInsights(date)`, возвращающий массив `{ time, label, direction }`.
   - **Линия "сейчас"** (`NowIndicator`): горизонтальная линия через всю ширину колонки,
     цвет `--danger` (тонкая, 1–2px), с маленькой точкой/меткой слева на пересечении с осью
     времени; обновляется раз в минуту через `setInterval`; скрывается для не-сегодняшних дней.
   - **Плавающая кнопка добавления** (`FAB`): круглая, `56px`, фиксирована в правом нижнем
     углу таймлайна (`position: sticky`/`fixed` относительно скролл-контейнера), фон —
     градиент акцента (как существующая `plAdd` кнопка, но круглая), иконка `+`; клик открывает
     тот же шит создания задачи/события, что и в текущем Planner (`plNew`/`plAdd` логика),
     расширенный полями времени начала/окончания.
4. Под таймлайном (или в самом верху, по вкусу) — оставить строку добавления задачи в стиле
   существующего `plNew` инпута (для быстрого добавления без времени, попадёт в бэклог/на
   день без тайм-слота, отображается как компактная строка над или под шкалой, как «today's
   loose tasks»).

#### 6.2.2 Недельный вид (Week grid timeline) — новый компонент `WeekTimeline`
- Верхний ряд — 7 колонок-заголовков с коротким днём недели + числом (тот же стиль, что
  `plWeekStrip`, но растянутый на всю ширину как заголовки колонок таблицы).
- Ниже — общая часовая сетка слева (одна ось времени на всю неделю, как в референсе-планшете)
  и 7 колонок-дней справа, разделённых тонкими вертикальными линиями `--border-subtle`.
- В каждой колонке — те же `TimelineEventCard`, что и в дневном виде, но более компактные
  (меньший шрифт, `Small/12px`, название события в 1 строку с обрезкой `text-overflow`);
  ширина колонки = `(100% - шкала времени) / 7`.
- Клик/тап по дню (по заголовку колонки или долгий тап по пустой области колонки) —
  **разворачивает** этот день в полноэкранный `DayTimeline` (см. 6.2.1) с анимацией перехода
  (растягивание колонки на всю ширину, `--m-complex`/`420ms`/`--e-settle`).
- Линия "сейчас" рисуется только в колонке сегодняшнего дня, на всю ширину только этой
  колонки (не всей недели).
- Скролл — общий вертикальный для всех 7 колонок одновременно (синхронизированный скролл, как
  в нативных календарях).
- На мобильном экране Week-вид можно горизонтально скроллить/свайпать между неделями, либо
  сжимать колонки (адаптировать по ширине экрана — на телефоне неделя, скорее всего, должна
  превращаться в горизонтальный свайп по дням, а не в 7 узких колонок — принять решение в духе
  правила "не просто сжимать десктоп", см. `03_SCREEN_COMPOSITION_RULES.md`: на мобильном при
  ширине <480px по умолчанию открывать день, а «неделя» становится верхней полоской-навигатором
  (как в дневном виде), с возможностью через кнопку/жест увидеть недельную сетку в
  горизонтальном скролле).

#### 6.2.3 Переключение День ⇄ Неделя (общие правила)
- Единое состояние выбранной даты (`selectedDate`) общее между Day/Week/Month видами — при
  переключении вкладки день не сбрасывается.
- Сохранить все существующие данные задач (`plWeek`, `plMonthCells`, структуру task-объектов:
  `id, title, day, done, prio, due, rep, subs`) — расширить модель задачи опциональными полями
  `startTime`, `endTime` (ISO-время или минуты от полуночи) для тех задач/событий, у которых
  задано время. Задачи без времени продолжают отображаться как раньше (список) в Бэклоге и как
  "loose tasks" в дне.
- Анимация разворота — shared element transition: колонка дня в недельном виде и сам дневной
  экран должны визуально быть "одним и тем же объектом", растягивающимся между состояниями
  (использовать существующий motion-токен `complex/420ms` + `settle` easing).
- Свернуть день обратно в неделю — явная кнопка-стрелка (шеврон вверх/лево) в шапке дневного
  вида + системный "назад" (браузерная навигация/свайп-назад на мобильном должны тоже
  сворачивать, а не выходить из Planner целиком).
- Respect `prefers-reduced-motion` — при уменьшенном движении заменить разворот на простой
  fade/cross-fade без масштабирования.

#### 6.2.4 Состояния для DayTimeline/WeekTimeline (по аналогии с остальным приложением)
- Loading — skeleton-полосы вместо событий на каждый час.
- Empty (день/неделя без событий) — тонкая шкала времени без карточек + текст-подсказка и
  кнопка "Добавить событие", без "cardboard cemetery" картинок.
- Offline — компактный статус-бейдж сверху таймлайна, данные остаются видны (последний
  синхронизированный снимок), новые действия помечаются "pending sync".
- Error — инлайн-нотис над шкалой с кнопкой "Повторить".

## 8. ACCEPTANCE CRITERIA (готово, когда всё это верно)

- Все 24 экрана представлены, ни одна функция не удалена.
- Ни один основной сценарий не стал длиннее без явной UX-причины.
- Навигация предсказуема, единая терминология.
- У каждого экрана — одна ясная цель и очевидное следующее действие.
- Часто используемые действия (выполнить привычку/отменить/добавить, лог тяги/срыва,
  чек-ин настроения, старт/пауза/резюме/финиш фокуса, старт тренировки/лог подхода/
  отмена/редактирование/старт отдыха/пропуск/финиш, лог питания/воды) — быстрые, без лишних
  экранов.
- Единый визуальный язык компонентов: одинаковые радиусы, типографика, иконография,
  статус-грамматика по всему приложению.
- Акцент (ice-blue) использован скупо и осмысленно; никакого фиолетового AI-градиента;
  никакого избыточного стекла (glass — акцент, не весь продукт).
- Touch target ≥44px, видимый фокус, статус не только цветом, читаемый контраст, логичный
  порядок фокуса, поддержка reduced-motion.
- **Планер:** день и неделя — не два отдельных экрана, а один календарь, который
  разворачивается/сворачивается друг в друга; все существующие функции задач (чекбоксы,
  подзадачи, приоритет, повтор, меню, бэклог, месяц) сохранены и работают также, как раньше.
- Финальный вопрос: если пользователь открывает приложение впервые, может ли он за секунды
  ответить — «Где я? Что важно? Что мне делать? Что произошло после того как я это сделал?»
  Если нет — редизайн не закончен.
